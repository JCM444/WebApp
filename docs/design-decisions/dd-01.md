# 01: Wie binden wir die relationale Datenbank an?

| Property | Value |
|--:|:--|
| **Status** | 🟢 Decided |
| **Updated** | 23.11.2026 |
| **Lead** | Helen Wolf |

## Problem Statement

Für StudyCircle müssen Daten wie Benutzerkonten (User) und Lernsessions (StudySession) persistent in einer relationalen Datenbank gespeichert werden. 

**Die Anforderungen lauten:**
- Einfache Umsetzung von CRUD-Operationen (Erstellen, Suchen, Absagen von Sessions)
- Schnelle Entwicklung und geringer Boilerplate-Code in Flask
- Leichte Anpassbarkeit der Datenmodelle im Semesterverlauf

**Zu entscheiden:** Nutzen wir direktes, rohes SQL (z. B. via sqlite3) oder Flask-SQLAlchemy?

## Decision

Wir verwenden **Flask-SQLAlchemy**.

## Regarded options

### Option 1: Flask-SQLAlchemy (ORM)

Datenbanktabellen werden als Python-Klassen (db.Model) definiert, Abfragen laufen über Methodenaufrufe.

**Vorteile:** Deutlich weniger Code für Standard-CRUD-Operationen und saubere Integration in Flask.

**Nachteile:** Zusätzliche Abhängigkeit; Einarbeitung in ORM-Konzepte (Sessions, Lifecycle) nötig

### Option 2: Rohes SQL (via sqlite3)

SQL-Statements (SELECT, INSERT) werden als handgeschriebene Strings im Python-Code formuliert und über eine DB Connection ausgeführt.

**Vorteile:** Keine externen Bibliotheken nötig (in Python enthalten)

**Nachteile:** Viel Boilerplate-Code, Schema-Änderungen müssen in allen SQL-Strings händisch gesucht und angepasst werden.

## Implementierung & Test

Flask-SQLAlchemy wurde in der Codebasis integriert und erfolgreich getestet:

```python
# db.py 
from flask_sqlalchemy import SQLAlchemy
db = SQLAlchemy()

# features/organization/models.py (konzeptionell)
class StudySession(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    ...
```

**Ergebnis:** Tabellen werden mit db.create_all() automatisch initialisiert. CRUD-Routen können Datensätze direkt als Python-Objekte anlegen (db.session.add(...), db.session.commit()), ohne dass manuelle SQL-Strings verwaltet werden müssen.
